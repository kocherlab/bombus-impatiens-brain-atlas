# BIMP-ST: a whole-brain spatial transcriptomic atlas of *Bombus impatiens*

Code that reproduces the analyses, figures, tables and Supplementary Data of a
study of the bumble bee brain: a three-dimensional 10x Xenium
atlas of a queen and a worker brain (101-gene panel), mapped to single-nucleus
RNA-seq cell types with Tangram2, with queen-versus-worker comparisons and MALDI
mass-spectrometry imaging. It also holds the source of the interactive 3D viewer
of the atlas. Citation metadata: [`CITATION.cff`](CITATION.cff).

## Layout

```
README.md      this file, with the figure map below
src/bimp_st/   shared Python package: canonical data paths and loaders (paths.py),
               site configuration (site.py), the cell-type vote, regions, styles
scripts/       the analyses, one folder per topic (map: scripts/README.md);
               every figure, table and Supplementary Data generator is here.
               scripts/paper/ holds the figure registry, the build Snakefile,
               the integrity checks and this repository's build tools
pipelines/     Snakemake pipelines that build the atlas objects the scripts read
               (one folder per pipeline; see "The pipelines" below)
data/          small inputs kept in git: the Xenium panel tables (panel/), the
               genome-annotation inputs (genome/) and the hand-drawn brain-region
               annotations (annotations/<brain>/); large data are downloaded here
viewer/        the 3D atlas website (its own README; deploy/ publishes it)
config/        site template, pinned environments (envs/), Snakemake profiles,
               Slurm launcher
tests/         unit tests
```

## Rebuilding the figures and tables

One command rebuilds every figure, table and Supplementary Data file from the
atlas objects and then runs the checks (Snakemake is run as a tool, not
installed in the environment):

```bash
SMK="uvx --from snakemake --with snakemake-executor-plugin-slurm snakemake"
$SMK -s scripts/paper/Snakefile -n            # what would run (needs the inputs in "Data")
$SMK -s scripts/paper/Snakefile --cores 4     # every figure, table, Supplementary Data file, then the checks
```

Both need the atlas objects and analysis inputs listed under [Data](#data):
Snakemake resolves every rule's inputs even for a dry run (`-n`), so without
them it stops at the first missing file (a `MissingInputException`).

"Runs first" are analysis steps the Snakefile runs before the generator;
"Built on" names the pipelines whose outputs the generator reads, as detected
from the paths its source names (a guide, not a full input list). The table is
generated (`scripts/paper/make_figure_map.py`) and a unit test fails when it is
out of date.

The manuscript sources are a separate repository; point `BIMP_MANUSCRIPT` at a
clone of it (default `submodules/bombus_impatiens_atlas_manuscript`) to compare
against or copy figures into it.

### The pipelines

Each pipeline is run from its folder with a profile from `config/profiles/`
(`local`, or `slurm` for a cluster), for example
`cd pipelines/combined_atlas && $SMK --profile ../../config/profiles/local -n`.
The per-brain runs sit one level deeper, so from `pipelines/wholebrain/queen`
or `pipelines/wholebrain/worker` the profile is `../../../config/profiles/local`.
The analyses are Snakefiles of their own, run from `pipelines/analyses` with
`-s region_relabel.smk` or `-s atlas_analyses.smk`. Without the data, a dry
run of `combined_atlas`, `snrna_reference`, `maldi`, `subcellular` or
`atlas_analyses.smk` (like `scripts/paper/Snakefile`) stops at the first missing
input; one of `wholebrain/queen`, `wholebrain/worker`, `region_relabel.smk` or
`scripts/gene_annotation/Snakefile` lists the jobs it would run, and running them
needs the inputs.

| Pipeline | Builds |
|---|---|
| `pipelines/snrna_reference` | the single-nucleus RNA-seq reference: QC, clustering, cell-type annotation |
| `pipelines/wholebrain` | per brain (`queen/`, `worker/`): Xenium crops, region labels, PASTE3 3D alignment, clustering |
| `pipelines/combined_atlas` | both brains combined: clustering and the Tangram2 cell-type mapping |
| `pipelines/analyses` | `region_relabel.smk`: region flags from the newest annotations and their dependents; `atlas_analyses.smk`: supplementary analyses (run with `-s`) |
| `pipelines/maldi` | MALDI imaging: ingest, QC, alignment (`raw_extraction/`: ion images from the raw imzML) |
| `pipelines/subcellular` | subcellular transcript localisation (bento-tools, own environment) |

`pipelines/wholebrain` and `pipelines/combined_atlas` include stochastic GPU
steps (alignment, mapping) that every spatial number depends on; the figures
are rebuilt from their deposited outputs, not by re-running them.

## Data

Raw and processed sequencing data will be deposited at the Gene Expression
Omnibus (accession: to be added), the BIMP_v4 genome assembly and annotation at
NCBI (to be added), and the MALDI imaging data and micro-CT template volume at
Zenodo (DOI: to be added).

The figures are rebuilt from these objects. Put each at the path shown,
relative to the repository root (a symlink is fine); `src/bimp_st/paths.py`
names them. A generator that cannot find one stops with a `MissingInputError`
that names the file and points here.

| Input | What it is | Size (approx.) | Path | Availability |
|---|---|---|---|---|
| Combined atlas | both brains' Xenium cells (1,300,192), coordinates, expression, Leiden clusters (`paths.SPATIAL_COMBINED`) | 1.4 GB | `pipelines/combined_atlas/data/combined_clustered.h5ad` | to be announced |
| Tangram mapping | the canonical cell-type mapping of the combined atlas (`paths.CANONICAL_TANGRAM`) | 1.7 GB | `results/tangram/combined_clustered_g2_R2_s42_tangram.h5ad` | to be announced |
| Region-specific mappings | central-brain, optic-lobe and stitched Tangram runs (`paths.CANONICAL_CENTRAL`, `CANONICAL_OPTIC`, `CANONICAL_STITCHED`) | 1.4 GB, 0.1 GB, 1.7 GB | `results/tangram/combined_clustered_{central,optic,stitched}_colfix_tangram.h5ad` | to be announced |
| Per-brain atlases | aligned, clustered queen and worker objects with region flags (`paths.ALIGNED_QUEEN`, `ALIGNED_WORKER`) | 0.7 GB, 0.6 GB | `pipelines/wholebrain/{queen,worker}/data/aligned_clustered.h5ad` | to be announced |
| Per-section Xenium crops | one object per brain section in slide microns (30 queen, 35 worker), read for distances and section plots | 66 GB in all | `pipelines/wholebrain/{queen,worker}/data/output-XETG00151__*.h5ad` | to be announced |
| snRNA-seq reference | annotated reference, combined and per region (`paths.SN_COMBINED`, `SN_CB`, `SN_OL`) | 1.3 GB, 0.9 GB, 0.35 GB | `data/sn/BIMP_atlas_qw_{combined,CentralBrain,OpticLobe}.h5ad` | to be announced |
| Large-type Kenyon-cell snRNA-seq | the Large-type Kenyon-cell nuclei the subcluster analysis reads | 0.26 GB | `data/sn/adata_ltKC_preprocessed.h5ad` | to be announced |
| MALDI imaging, processed | aligned per-spot peptide intensities and voxel volumes | 5.3 GB | `pipelines/maldi/data/` | to be announced |
| MALDI ion images | imzML-derived ion images and peak features (md5s in `ion_out.md5`) | 0.9 GB | `pipelines/maldi/raw_extraction/ion_out/` | to be announced |
| Analysis outputs | tables the generators read under `results/` (compositions, DE fits, caches) | varies | `results/` | rebuilt by the analysis steps `scripts/paper/Snakefile` runs first, from the inputs above |

Rebuilding the inputs themselves (the snRNA-seq counts and caste DE, the
genome-annotation tables, the MALDI extraction, the deposit staging) also
reads data held outside the repository, through the site keys in
`config/site.example.toml` (`snrna_source`, `genome_dir`, `maldi_raw`, ...);
rebuilding the figures from the objects above needs none of them.

The small inputs in `data/` are described in
[`data/annotations/README.md`](data/annotations/README.md),
[`data/genome/README.md`](data/genome/README.md) and
[`data/panel/README_gene_names.md`](data/panel/README_gene_names.md).

## Environment

Python 3.12 and [uv](https://github.com/astral-sh/uv); a CUDA GPU only for the
alignment and Tangram steps. Two dependencies are installed from source at the
commits every result was produced with:

```bash
git clone https://github.com/Genentech/tangram2 submodules/tangram2
git -C submodules/tangram2 checkout 0af3056ff537c4e063b960a5f02a60b1711a89c4
git clone https://github.com/raphael-group/paste3 submodules/paste3
git -C submodules/paste3 checkout b1f3f844275f7f3fe53e3d9d29880076d1796a04

uv sync
uv pip install --no-deps -e submodules/tangram2
```

tangram2 is installed without its dependencies (its `setup.py` pins a full
environment that conflicts with this one; see `pyproject.toml`). The optional
MOSAICField aligner (no result depends on it) is
<https://github.com/raphael-group/MOSAICField> at `7d3abadd5ca74c5d6e72ac500a86bbc66bdd2f4b`.
`config/envs/requirements-freeze.txt` lists the exact versions of the
environment the analyses were run in. Side environments, each built from its file
in `config/envs/`:

- `.venv-deseq2` (`config/envs/deseq2.txt`): the pseudobulk DESeq2 caste fits;
- `.venv-cnmf` (`config/envs/cnmf.txt`, Python 3.10): the joint cNMF and GSEA
  pipeline in `scripts/caste_de/cnmf_gsea/`;
- `vendor/pylibs`: harmonypy 2.0.0, put on the path by the
  `pipelines/analyses/atlas_analyses.smk` rules
  (`uv pip install --target vendor/pylibs harmonypy==2.0.0`);
- the bento-tools subcellular analyses (`pipelines/subcellular`) run in an
  environment of their own.

Run scripts from the repository root with both `src/` and `scripts/` on the path:

```bash
PYTHONPATH=src:scripts .venv/bin/python scripts/<folder>/<script>.py
```

Inputs that are not in the repository (the snRNA-seq analysis tree, the genome,
raw MALDI exports, and `data/` when it lives outside this checkout) resolve through
`bimp_st.site`: copy `config/site.example.toml` to `config/site.toml` (or set
`BIMP_<KEY>`). Regenerating the figures and numbers from the deposited objects
needs none of them. Stand-alone Slurm launchers are submitted with
`bash config/sbatch.sh <launcher.sh>`; set your cluster's partition and QOS in
`config/profiles/slurm/sbatch.env`.

## The 3D viewer

`viewer/` is the source of the interactive atlas website: the data export from
the atlas objects (`export_data.py`), the WebGL front end (`src/`), the build
scripts and the deploy scripts. Building and publishing it is described in
[`viewer/README.md`](viewer/README.md) and
[`viewer/deploy/README.md`](viewer/deploy/README.md). Rebuilding the
figures does not need it.

## Checks

```bash
PYTHONPATH=src:scripts .venv/bin/python scripts/paper/verify_manuscript_figures.py  # figures, tables, Supplementary Data against their sources
PYTHONPATH=src:scripts .venv/bin/python scripts/paper/check_data_provenance.py --baseline scripts/paper/provenance_baseline.txt
```

The figure check compares against a manuscript checkout (`BIMP_MANUSCRIPT`).
Without the data, `verify_manuscript_figures.py --registry-only` checks the
registry; `check_data_provenance.py` (`--help` lists its checks) reads only
code. Without a manuscript checkout, the manuscript-dependent parts of the
last two are skipped with a message. `bash scripts/paper/ci.sh` runs these with
ruff, the unit tests and `scripts/paper/leak_lint.py` (comments and docstrings
describe what code computes, never its results; environment: `config/envs/ci.txt`).
Verification of the quoted numbers (each recomputed from its source) is not
part of this release.
